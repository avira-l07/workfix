FINDING-BY-FINDING RECORD
========================
F01 - FIXED IN DEPENDENCY GRAPH
Problem: ML Kit resolved vulnerable OkHttp 3.0.0.
Change: Constrained the transitive runtime to OkHttp 4.12.0. ML Kit remains the translation engine.
Verification / boundary: 169 resolved runtime Maven modules checked with OSV: no advisories returned. Native/AAR/tool/test libraries are outside this scan; this is not a security certification.

F02 - MANUAL KANNADA PATH FIXED; QUALITY LIMITS REMAIN
Problem: Tiny produced Latin/wrong-language text and hallucinated on a direct digital-silence probe.
Change: Manual Kannada now downloads and uses the pinned dedicated CTC model. Added exact all-zero/empty waveform guards in both normal finalization and direct decode. No quiet-speech threshold was introduced. Kannada added to the in-app self-test.
Verification / boundary: Same 30 clean desktop WAVs: WER 169.80% -> 17.23%, native script 0/30 -> 30/30. Raw CTC still emits a character on 1/2-second zeros; the new app guard prevents native decoding for digital silence, verified by unit checks. Real background noise, Android audio capture and all two-phone outcomes: Not verified. Auto-detect still uses Tiny and is explicitly labelled unreliable for Kannada; select manual Kannada.

F03 - FIXED IN SHARED SENDER
Problem: 16,384 plaintext bytes became 16,400 encrypted bytes and exceeded the receiver limit.
Change: A shared guard reserves the 16-byte GCM tag: plaintext maximum 16,368 UTF-8 bytes, ciphertext maximum 16,384. Encoder bounds checked too. Rejected sends retain the message with a readable error; oversize retries stop. The chat input disables oversize sends.
Verification / boundary: Regression covers the exact Hindi UTF-8 boundary through encrypt/frame/decode/decrypt, the first oversize byte, unchanged next counter, and emoji round-trip. Final translated payloads are guarded too.

F04 - MITIGATED; REPLACEMENT MARATHI VOICE STILL NEEDED
Problem: The MMS Marathi voice silently skipped U+0949 (ॉ) in the doctor phrase.
Change: Load uses a native Marathi startup phrase. Synthesis checks actual voice vocabulary before native generation. Unsupported Marathi letters/marks produce an explicit voice error; original text is preserved. Unannounced Android TTS fallback is blocked for Marathi and Kannada as well as the original strict languages.
Verification / boundary: Unit checks cover the native startup phrase, डॉक्टरांना बोलवा, and foreign letters. Published facebook/mms-tts-mar vocabulary was fetched and also lacks this vowel. Reinstalling that voice cannot repair it. This fixes silent loss, not pronunciation. A broader Sherpa-compatible voice or retraining, plus listener assessment, remains required.

F05 - FIXED IN SOURCE; DEVICE UI NOT VERIFIED
Problem: Static TAC-RELIEF-04 and cohort/channel labels looked like live operational data.
Change: Hub and Connect use verified peer identity and actual direct connection state; absent identity is labelled unavailable/pending. Removed the invented channel/cohort labels.
Verification / boundary: Source checks confirm those strings are removed. Real radio/satellite/multi-hop integration is not created or claimed.

F06 - NATIVE APPEARANCE IMPLEMENTED; VISUAL DEVICE CHECK PENDING
Problem: Preview appearance options were absent in native UI and fixed light colors broke dark mode.
Change: Native Compose theme supports System/Light/Dark and Ocean/Forest/Iris/Ember. Settings persist atomically in DataStore. MainActivity applies the saved theme. Existing screens use semantic surface/text/status colors; drawing colors are captured in composable scope. Color changes animate over 180 ms.
Verification / boundary: All eight scheme combinations pass tested 4.5:1 text contrast pairs. Persistence/concurrent preference updates pass. These numeric token checks do not certify every rendered screen, transition, font size, TalkBack order or sunlight readability. Full HTML-preview workflow parity is not claimed.

F07 - FIXED AT PROFILE PARSER
Problem: Empty IDs, unsupported protocol versions and malformed profiles could replace active peer identity.
Change: Reject unsupported/non-integer versions, malformed IT-XXXX-XXXX IDs, blank/control/oversize names, missing/unknown/duplicate languages and oversize payloads. Rejected profiles never reach the existing identity-update branch.
Verification / boundary: Regression covers valid round-trip plus malformed JSON, blank IDs, v999/v1.5/string versions, control text, duplicate/unknown languages, and byte/name limits. Existing blank-row DAO guard remains.

F08 - FIXED IN SOURCE
Problem: Unconditional profile logs exposed peer IDs and names in release logs.
Change: Profile sent/received logs now describe validation state without identity values.
Verification / boundary: Source check performed. Installed release log capture and external privacy certification: Not verified.

F09 - FIXED AND STRESS-TESTED
Problem: Concurrent decrypt calls could authenticate the same counter before replay state was committed.
Change: After AEAD authentication, require the existing synchronized replay-window accept/commit to succeed before returning plaintext.
Verification / boundary: 50 rounds x 8 concurrent decrypt calls: exactly one acceptance per authenticated packet in the passing regression. Existing tamper/session tests also pass. No remote exploit or phone attack was claimed.

F10 - FIXED AND TESTED
Problem: Native notes grouped offsets 2..7 as seven days, while preview used 2..6.
Change: Native rolling seven-date interval now covers today through six days ago, with Today/Yesterday kept separate.
Verification / boundary: Fixed-date tests cover today, yesterday, 6/7/10 days ago, last month and 13 months ago, plus local midnight and a Europe/Berlin daylight-saving boundary. Note deletion isolation tests remain green.

F11 - REMOVED FROM DEFAULT APK
Problem: Unused Nearby dependency and experimental CTranslate2 JNI increased the shipped runtime.
Change: Removed unused Nearby. CMake/CTranslate2 build is explicitly opt-in with -PitantraExperimentalTranslation=true; default APK uses existing ML Kit translation.
Verification / boundary: Fresh debug/release APK inventories contain 8 arm64 native libraries, no libitantra_mt_jni, and no ONNX weight assets. Selective downloads are preserved. JNI load-alignment metadata is >=16 KiB; this is not an Android device-load test.

F12 - FIXED IN SOURCE
Problem: Settings displayed an ANDROID_ID-derived hash/fake fallback rather than the peer protocol ID.
Change: Settings reads the persistent DeviceProfileManager IT-XXXX-XXXX identity used by the handshake. Missing identity is labelled unavailable.
Verification / boundary: Source wiring checked and builds pass. Pairing-screen comparison on phones: Not verified. An unrelated internal node-ID hash is still used by the coordinator and is not presented as this Settings ID.

F13 - COMPATIBILITY AND CLEANUP FIXED; DEVICE REPRODUCTION PENDING
Problem: API29 used the API30 microphone foreground-service type; startup failures left operation flags/wakelocks running.
Change: API26-29 use the two-argument foreground call; API30+ use microphone type. Acquire a bounded renewable wakelock only after foreground startup succeeds. Clear readiness on stop/failure, report errors to the hub, wait for service readiness before capture, and stop capture on failure/timeout. Preserve an already-active emergency when continuous startup fails.
Verification / boundary: API type compatibility unit check passes. Android permission denial, service lifecycle, screen-off capture and wakelock behavior were not exercised on a phone.
