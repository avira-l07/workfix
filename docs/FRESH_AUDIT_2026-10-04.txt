APPLICATION CONTEXT
===================
Purpose: offline speech-to-text, optional local translation, small encrypted
peer packets, receiving-side speech synthesis, chat history, voice transcripts,
location sharing, and emergency messages.
Production frontend: native Kotlin / Jetpack Compose Android application.
Storage: Room version 5 with SQLCipher; separate protected preferences/files.
Speech: sherpa-onnx native STT and offline VITS/MMS-style voices.
Translation: active application engine is ML Kit offline translation, plus
deterministic emergency phrase handling. General Malayalam/Odia translation
is unsupported. Speech support does not imply translation support.
Transports: Bluetooth Classic RFCOMM and Wi-Fi Direct TCP, one active transport.
Backend: no hosted application backend, REST API, WebSocket service, cloud
account, payment flow, admin panel, or server-side user roles found.
Roles: local operator and a peer in a mutually SAS-verified session; Android
platform permissions independently gate microphone, radios, and location.
Model provisioning accesses public Hugging Face artifacts and Google-managed
translation-model installation. Installed speech inference is local.

Three different UI/source categories must be distinguished:
- D:\new itantra\app\src\main\java: production native application.
- D:\new itantra\itantra_light_ui: standalone HTML/CSS/JavaScript design preview.
- D:\new itantra\old ui and stitch_ui_curated_v8: reference/export material;
  not the active Android application source set.
The HTML preview is not a WebView wrapper around the native backend.

F03 - MEDIUM - Outgoing message size is incompatible with receiver bounds
Location: D:\new itantra\app\src\main\java\com\itantra\core\transport\packet\PacketEncoder.kt:59;
  D:\new itantra\app\src\main\java\com\itantra\core\transport\packet\PacketDecoder.kt:18;
  D:\new itantra\app\src\main\java\com\itantra\core\transceiver\TransceiverCoordinator.kt:1985;
  D:\new itantra\app\src\main\java\com\example\itantra\ui\screens\chat\DedicatedChatScreen.kt:313.
Repro: run encryptedPayloadBoundaryProbe in the fresh audit suite; encrypt
16,384 plaintext bytes, encode them, then decode the resulting body.
Expected: reject over-limit input locally with a clear message or fragment it
according to an explicit protocol before sending.
Actual: the encoder accepts it; AES-GCM adds 16 bytes; the 16,400-byte payload
is rejected by the receiver. 16,368 plaintext bytes fit the current cipher limit.
The chat input and sendTextMessage path have no corresponding UTF-8 byte cap.
Evidence: fresh-test-results.xml. Both radio receive loops also reject frames
above MAX_FRAME_BODY_SIZE. Actual phone disconnect behavior was not exercised.
Suggested fix: define a shared encrypted wire limit, validate final translated
UTF-8 payload bytes including AEAD overhead, guard the encoder, and explain
oversized input in the UI. Keep the original transcript intact on failure.

Expected API behavior: each counter can succeed only once.

the counter, or serialize decrypt. Never let unauthenticated packets advance
the replay window.
