# Storage encryption and wipe report

Baseline tag: `pre-encryption-baseline`.

## Changes

| Data | File/location | Implementation |
|---|---|---|
| Chat messages, transcripts, GPS metadata, delivery state | `databases/itantra.encrypted.db` and SQLite sidecars | `core/storage/EncryptedDatabase.kt`, SQLCipher 4.19.0 through Room `SupportOpenHelperFactory` |
| Database passphrase | `no_backup/storage_keys/database.key` | `DatabasePassphrase.kt`: 32 random bytes, AES-256-GCM wrapped by a non-exportable Android Keystore key. Only the encrypted envelope and IV are persisted. SQLCipher receives a printable hex representation in memory. |
| Emergency records, including recovery file | `files/emergency_records.json[.tmp]` | `EmergencyPersistenceStore.kt`, versioned AES-256-GCM envelope, fresh IV per write, authenticated reads, fsync then atomic replacement |
| STT/TTS diagnostic sessions | `files/benchmarks/*.json` | `PrivateContent.kt` and `LocalBenchmarkRepository.kt`; encrypted despite the retained filename extension |
| Operator name and local profile identity | Settings DataStore and `itantra_device_profile.xml` | `PrivateContent.kt`, `StoragePrivacy.kt`, `SettingsRepository.kt`, `DeviceProfileManager.kt`; encrypted values, legacy values converted at startup |

Keys are generated by `AndroidKeyProvider` without requiring user authentication, permitting background/reboot access after the Android user unlocks credential-encrypted app storage. Key creation is serialized across adapter instances. Lost/invalid database keys produce a recovery screen with preserved source files and an explicit wipe option. Unrecoverable emergency files start an empty emergency store and display a warning. No silent replacement database is opened on a migration failure.

Room schema remains version **3**. `MIGRATION_1_2`, `MIGRATION_2_3`, and the exported schemas are unchanged. No destructive migration fallback was added. Wire packet classes and session cryptography are unchanged. Speech/translation changes are limited to removing sensitive logs and diagnostic audio persistence.

## Existing-install migration

The file-level migration exports legacy `itantra.db` using `sqlcipher_export`, preserves `user_version`, compares counts for every application table (including Room metadata), checks SQLite integrity, opens the copy through Room's existing schema/migrations, checkpoints it, and atomically promotes it. The legacy database and sidecars are removed only after the encrypted database opens successfully. A retained legacy database is re-exported on the next attempt. Corruption callbacks preserve files rather than deleting them.

**Native migration execution is not yet tested on hardware.** No phone or emulator is connected. The compiled Android test seeds **3 message rows**, expects **3 identical rows after migration**, verifies schema version 3, and checks deletion of the old database and absence of a plaintext marker. These are test assertions, not measured successful migration counts. Additional compiled Android tests cover fresh encrypted storage, wrong-key rejection, failed schema validation retaining a legacy row, and wiping/reopening an empty database.

Host tests successfully cover legacy emergency JSON migration, authenticated encrypted round trips, tamper rejection, encrypted temp-file recovery, and the existing interrupted-write regression.

## Wipe

Settings and the storage-recovery screen offer **Wipe all data**. A confirmation dialog requires a deliberate hold. The flow stops sessions/service, clears coordinator memory, and exits the main app process. A private, non-exported `:wipe` activity waits for that process to disappear before deleting data, preventing queued Room/DataStore writers from recreating it. It deletes database files and sidecars, emergency files, wrapped passphrase, all three storage key aliases, diagnostic sessions, app identity/settings, legacy debug audio and caches. A durable pending marker makes interruption retryable and blocks normal startup until cleanup succeeds. A fresh main process then starts with default app state.

Downloaded `language_packs`, `translation_models`, ML Kit model storage, and the cached Silero model are preserved. Host wipe tests check deletion, key invalidation, model preservation and idempotence. End-to-end process restart and the hold gesture are **not yet tested on hardware**.

## Plaintext audit

The manifest already had `android:allowBackup="false"`; it remains false. Backup XML files previously contained sample/default rules. Explicit exclusions now cover files, databases, preferences, root and external storage for cloud backup and device transfer.

Changed logging instances:

1. `TransceiverCoordinator.handleIncomingLocationPacket`: removed latitude from the invalid-coordinate warning.
2. The same handler: removed longitude from the invalid-coordinate warning.
3. Continuous speech processing: removed the full Whisper translation from its log.
4. Push-to-talk processing: removed the full Whisper translation from its log.
5. `MlKitOfflineTranslationEngine.translate`: removed the first 50 characters of non-Devanagari translated output.
6. Removed the debug WAV-save success/error logs together with both microphone WAV writes.
7. Emergency persistence errors now log generic failure messages rather than exception traces.
8. SQLCipher Java logging uses `NoopTarget`; application migration failures use a content-free message.

No raw user message, transcript, coordinate or storage-key value was found in the remaining explicit application logs. Counts, language codes, static TTS smoke-test text and operational error metadata remain. This is a source audit, not a device logcat capture or an audit of every third-party native library.

Plaintext that remains intentionally:

- Downloaded/bundled models, language packs, static phrasebooks, benchmark assets and Silero model; these contain no user recordings.
- Language selections, model-download metadata, VAD/volume and other non-content settings. Operator names and local profile identity values are encrypted.
- Filenames, timestamps, language codes, file sizes and ordinary SQLite sidecar names; encryption does not conceal all metadata.
- A legacy plaintext database is retained if migration/verification fails, to avoid data loss. A failed emergency conversion similarly retains the recoverable source.
- Text/audio are necessarily available in process memory while used. Existing notification text, user-triggered clipboard copies and coordinates opened in an external map app are outside this app's encrypted files. Storage encryption cannot revoke copies already made outside the app.

Live microphone WAV persistence has been removed in debug and release builds; existing `debug_ptt.wav` in app cache/external files is deleted during privacy preparation. Diagnostic JSON is migrated to encryption. No other active application write path for user audio was found.
